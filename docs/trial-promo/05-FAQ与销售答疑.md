# OpenAtlas FAQ 与销售答疑

## 1. OpenAtlas 和普通 AI 聊天工具有什么区别？

普通聊天工具强调“问答”。OpenAtlas 强调“企业任务闭环”。

区别主要在四点:

- 有明确数字员工角色，而不是一个泛用助手。
- 能处理文件、Skill、记忆和多员工协作。
- 过程可展示任务进展、工具阶段、上下文来源。
- 结果可以形成报告、HTML、表格、清单等交付物。

## 2. 为什么要做“数字员工”，而不是直接让用户写 Prompt？

企业用户不应该从空白 Prompt 开始。数字员工把岗位角色、能力边界、输出格式和协作方式预先固化，用户只需要描述业务任务。

这降低了使用门槛，也提升了输出稳定性。

## 3. Skill 是不是黑盒？

不是。产品设计目标是让管理员和用户看清:

- Skill 的能力说明
- 输入输出示例
- 适用员工
- 风险等级
- 版本和安装状态
- 本轮是否实际调用或注入

首批试用阶段，Skill 可解释性仍会继续加强。

## 4. 文件会不会串到其他用户或租户？

OpenAtlas 按租户、用户、员工、会话、文件和交付物做隔离设计。普通用户只能看到自己有权限访问的会话、文件和交付物。管理员可按权限查看管理数据。

试用阶段建议不要上传敏感原始数据，优先上传脱敏材料。

## 5. 模型回答是否一定准确？

不保证。OpenAtlas 的目标不是让模型“永远正确”，而是让用户看清依据、上下文、文件、Skill 和任务过程，并能继续追问、修正、归档。

涉及法律、财务、投资、人事等高风险场景，输出应作为辅助分析，需要专业人员复核。

## 6. 为什么有时会出现审批？

当底层运行涉及高风险、不确定或需要权限确认的动作时，系统应要求人工确认。审批机制是企业可控性的组成部分，不是异常。

## 7. 长任务为什么有时需要等待？

长任务可能涉及:

- 多轮模型调用
- 文件解析
- 工具调用
- 多员工接力
- 交付物生成

OpenAtlas 会展示运行中、等待、工具阶段、交付物入库等状态。后续会继续强化长任务回放、恢复和自动同步。

## 8. 现在最适合试用哪些场景？

优先选择“输入明确、文件明确、输出物明确”的任务:

- 合同审查
- 会议纪要
- 市场调研
- 经营分析
- 销售方案
- 招聘初筛
- 长文档解析
- 投资分析报告

不建议首批试用直接挑战完全开放、无材料、强实时、高风险决策类任务。

## 9. 试用期间如何判断是否值得继续推进？

建议看三类指标:

- 效率: 是否明显减少人工整理、分析、写作时间。
- 质量: 输出是否结构化、可引用、可修改、可交付。
- 管理: 是否能解释任务过程、权限边界和交付物来源。

## 10. 企业采购最关心什么？

通常不是“模型多聪明”，而是:

- 数据和权限是否隔离。
- 过程是否可审计。
- Skill 和工具是否可管。
- 结果是否能沉淀为交付物。
- 管理员是否能看到使用量、失败率、成本和健康状态。
