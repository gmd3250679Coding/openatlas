# OpenAtlas 开发日 Review 与阶段总结

日期: 2026-06-06
评审范围: `openatlas/` 后端、前端、Hermes Gateway 隔离启动脚本、交付文档。

## 结论

团队总体没有偏离上一版 Spec 的主方向: 已经把改造收敛到独立的 `openatlas/`，没有继续深改 Hermes 本体；也已经建立了 BFF/control plane、前端页面、租户级 Hermes Gateway、Skill Market、Memory Center、Dashboard、Audit、Runtime 管理等雏形。

但当前推进速度超过了基础契约的稳定程度。最需要立刻收口的是: 前端类型契约、租户运行时 fail-closed、Skill/Memory 权限边界、密钥与 CORS、安全启动、测试体系。否则后续功能越补越多，隔离模型会变得越来越难证明。

## 主要发现

### P0/P1 阻断项

1. 前端默认构建绕过 TypeScript 校验。
   - `openatlas/frontend/package.json:8` 把 `build` 改成了 `vite build`，而严格构建放在 `build:full`。
   - 实测 `npm run build` 成功，但 `npm run build:full` 失败，存在 `CommandCenter.tsx`、`EmployeeDetail.tsx`、`MemoryCenter.tsx`、`SkillMarket.tsx`、`api.ts` 等多处类型/接口不一致。
   - 风险: 页面可以被打包发布，但 API 契约、ID 模型、聊天事件类型已经失真。

2. 租户 Hermes Runtime 解析不是 fail-closed。
   - `openatlas/backend/app/services/hermes_client.py:84-105` 在租户 runtime 未运行或不存在时会 fallback 到默认 `TENANT_HERMES_BASE_URL`。
   - 风险: 某个租户的请求可能静默打到 demo/default Gateway，破坏“多用户/多租户服务、会话、记忆隔离”的核心目标。

3. 明文/硬编码密钥进入源码与默认配置。
   - `openatlas/runtime/launchers/hermes_api_server.py:76-97` 会写入具体 provider API key。
   - `openatlas/backend/app/core/config.py:35-46` 还有默认 API key、JWT secret、默认管理员密码。
   - `openatlas/backend/app/db/session.py:89-95` seed runtime 仍写入明文 demo key。
   - 风险: 代码仓库、日志、演示环境都可能泄露真实凭据；企业版必须先清理。

4. Skill 市场可见性与初始绑定逻辑有缺陷。
   - `openatlas/backend/app/main.py:894-899` 将所有 `Scope.employee` Skill 对所有同请求用户可见，没有限定目标员工、租户归属或创建者。
   - `openatlas/backend/app/main.py:398-411` 初始 Skill 绑定中，合法的 tenant/user scope skill 会落入 `else: continue`，实际只稳定绑定 global skill。
   - 风险: 个人/员工 Skill 的边界不可信，用户“引入、复制、定制”的模型会乱。

5. Memory 注入绕过了绑定模型，且把完整记忆内容发给前端事件。
   - `openatlas/backend/app/services/memory_resolver.py:18-49` 直接按 scope 全量纳入 active memory，没有使用 `MemoryBinding`、`injection_mode`、target 优先级。
   - `openatlas/backend/app/main.py:620-628` SSE 先发出完整 `eff`，再把所有 memory content 拼进用户消息，没有长度/token 上限。
   - 风险: 共享记忆、个人记忆、员工记忆无法精确隔离；敏感记忆内容可能被 UI 或日志侧暴露。

6. CORS 与 Gateway 暴露策略过宽。
   - `openatlas/backend/app/main.py:51-56` 使用 `allow_origins=CORS_ORIGINS + ["*"]` 且 `allow_credentials=True`。
   - `openatlas/runtime/launchers/hermes_api_server.py:152-159` Gateway CORS 配置为 `"*"`.
   - 风险: 与 Bearer token、浏览器环境组合后，不符合企业安全基线。

### P2 重要风险

1. 进程监管还不能证明“活着的是正确 Gateway”。
   - `openatlas/backend/app/services/supervisor.py:48-63` 健康检查只是 TCP 连接，未验证 `/health` 响应和 API key。
   - `openatlas/backend/app/services/supervisor.py:212-228` 用未引用/未转义的 shell command string 拼接路径与密钥。
   - 风险: 端口被其他进程占用也可能被视为健康；路径或密钥含特殊字符时启动不可靠。

2. 路径隔离守卫存在字符串前缀判断问题。
   - `openatlas/runtime/launchers/hermes_api_server.py:26-42` 使用 `startswith` 判断目录归属。
   - 风险: `/Users/macbook/.openatlas-bad` 这类路径可通过前缀判断，应改成 `Path.resolve()` + `is_relative_to()`。

3. 数据库演进方式仍是 MVP 级。
   - `openatlas/backend/app/db/session.py:51-64` 使用 `create_all` + 手写 `ALTER TABLE`。
   - `openatlas/backend/app/db/models.py:104-113` `api_key` legacy 字段仍存在，注释与 Phase 3 加密状态不一致。
   - 风险: 明天可以继续 MVP，但不能把它当成企业版迁移方案。

4. “全局 Memory”目前实际仍是租户内全局。
   - `openatlas/backend/app/db/models.py:229-245` `MemoryEntry.tenant_id` 非空。
   - `openatlas/backend/app/services/memory_resolver.py:18-23` 查询强制 `tenant_id == tenant_id`。
   - 风险: 无法表达真正平台级、不可被租户修改的全局记忆，只能复制到每个租户。

## 今日进展总结

已完成或基本成型:

- 独立 `openatlas/` 目录结构，方向上没有污染原 Hermes 服务。
- FastAPI BFF/control plane 雏形: auth、employee、session、chat stream、jobs、skill-market、memories、dashboard、audit、admin tenants/runtime。
- 前端已迁移并补了 Dashboard、Jobs、Skill Market、Memory Center、Skills 等页面。
- 租户级 Hermes Gateway 启动脚本、runtime launcher、supervisor 已搭出。
- 文档交付节奏清晰，已有 Phase 1/2/3/3.5-3.10 交付记录。

已验证:

- 后端核心模块 `py_compile` 通过。
- 前端 `npm run build` 通过，但这是非严格构建。
- 前端 `npm run build:full` 失败，类型问题必须修。
- 后端 `pytest` 当前不可用，环境缺少 pytest。
- 当前目录不是 git repository，无法用 git diff/status 做变更归因。

总体评价:

团队没有战略性跑偏，但有“功能先冲、契约滞后”的倾向。下一阶段不建议继续扩页面或新能力，应该先做 Stabilization Sprint，把隔离、权限、类型、测试、密钥清干净。

## 明日优先级

1. 恢复严格构建: `npm run build` 必须等价于 `tsc -b && vite build`。
2. Hermes runtime 改为 fail-closed: 无运行中租户 Gateway 时返回 503，不允许 fallback 到 demo。
3. 清理密钥: 移除源码中的真实 provider key，默认 secret/password/API key 必须来自 env 或本地未入库文件。
4. 修 Skill/Memory 权限: 员工/个人 scope 不可跨目标可见；resolver 必须使用 binding/injection_mode。
5. 补后端测试: 至少覆盖双租户隔离、Skill 可见性、Memory effective、runtime fallback、chat stream 注入。
6. 限制 CORS 与 Gateway 暴露面。
